Automatic Opinion Summarization from Customer Reviews

Line-by-line explanation of the code in Opinion_Summarization.ipynb

The project in one paragraph

I take 6,658 real Amazon headphone reviews. I clean them, train a TF-IDF + Logistic Regression model that tells positive from negative (using the star ratings as labels), split every review into sentences and score each sentence, find the product features as the most frequent nouns (POS tagging), count the positive and negative sentences for each feature, and finally pick real sentences from the reviews as the summary of what customers like and dislike.

Flow: load CSV → clean text → train model → split into sentences → score sentences → find nouns (features) → feature table → pick best sentences → print summary

Key terms in plain words

NLPNatural Language Processing: making computers work with human language, e.g. splitting text, tagging words, finding opinions.
Opinion summarizationReading many reviews and giving a short summary of what people like, dislike and talk about.
TokenizationCutting text into pieces. Sentence tokenization gives sentences, word tokenization gives words.
StopwordsVery common words (the, is, and). I remove them when looking for features, but NOT when training the model, because "not" is a stopword and it flips meaning.
POS taggingPart-of-speech tagging: labelling each word as noun (NN), verb (VB), adjective (JJ) and so on. I use it to find nouns, because features are nouns.
LemmatizationTurning a word into its dictionary form: batteries → battery. Different from stemming, which just chops endings (batteries → batteri).
TF-IDFTerm Frequency × Inverse Document Frequency. A word gets a high score if it appears often in this review (TF) but rarely in other reviews (IDF). "the" is everywhere, so it gets a low score; "crackling" is rare, so it gets a high score.
N-gramsGroups of N words in a row. 1-gram: "good"; 2-gram (bigram): "not good".
Logistic RegressionA simple classification model. It adds up word weights and squeezes the total into a number between 0 and 1 (the chance of positive) using the sigmoid function.
Train/test splitTraining data teaches the model; test data checks it on reviews it has never seen, like a surprise exam.
AccuracyCorrect predictions ÷ all predictions. Mine is 91.6%.
PrecisionOf the reviews the model CALLED negative, how many really were negative (0.72).
RecallOf the reviews that really ARE negative, how many the model found (0.70).
F1 scoreOne number that balances precision and recall (their harmonic mean).
Class imbalanceOne class has far more examples (here 5,107 positive vs 872 negative). class_weight="balanced" fixes this a bit.
Extractive summaryA summary made by picking real sentences from the text. The other type, abstractive, writes new sentences (like ChatGPT).
Aspect / featureThe part of the product an opinion is about: sound, battery, price.

def clean_text(text):
Defines my own function clean_text that takes one review and returns the cleaned version.
28
    text = re.sub(r"<.*?>", " ", str(text))              # remove HTML tags like <br />
re.sub(pattern, replacement, text) replaces every match of the pattern. <.*?> means "a <, then anything, then the nearest >", so HTML tags like <br /> become a space. str(text) makes sure the input is text even if a cell is empty.
29
    text = re.sub(r"[^a-zA-Z0-9.,!?' ]", " ", text)     # keep letters, digits, basic punctuation
[^...] means "any character NOT in this list". The list is letters, digits and . , ! ? ' and space. So emojis and symbols like # or * are replaced by a space. I keep full stops because sentence splitting needs them.
30
    text = re.sub(r"\s+", " ", text)                     # many spaces -> one space
\s+ means "one or more spaces/tabs/newlines". They are replaced by a single space, so "good    sound" becomes "good sound".
31
    return text.strip()
strip() removes spaces at the start and end, then the function gives back the clean text.

Likely viva questions

Q1. Why did you use machine learning and not just a list of good and bad words?

A word list (like VADER) cannot learn headphone language. My model learned from 6,000 real reviews that words like "returned" or "stopped" are negative, which a general list may not know. It also gives a probability, which I use to pick the most confident sentences.

Q2. Where did your labels come from?

From the star ratings: 4-5 stars = positive, 1-2 stars = negative. 3 stars are mixed, so I left them out of training. No manual labelling was needed.

Q3. Why Logistic Regression and not Naive Bayes or SVM?

All three work on TF-IDF. I chose Logistic Regression because it is simple, fast, gives probabilities directly, and its weights show which words it learned, so I can explain its decisions.

Q4. Why did you keep stopwords in TF-IDF?

Because negation words like "not" and "no" are in the stopword list. Removing them would turn "not good" into "good".

Q5. Why bigrams?

So "not good" or "stopped working" becomes one clue instead of two separate words.

Q6. Your model was trained on reviews but used on sentences. Is that OK?

Yes, sentences use the same words. I checked it on my own sentences: "They are not comfortable at all" scored 0.24 (negative) and "Great value for the price" scored 0.95 (positive).

Q7. Why work at sentence level?

Because one review can have both opinions: "Great sound. Battery died in a week." Sentence level puts each opinion with the right feature.

Q8. Why 0.65 and 0.35 as limits?

To leave a neutral zone. Sentences like "I bought these for the gym" are not opinions, so they get about 0.5 and are ignored. I picked the values by looking at examples; they can be tuned.

Q9. How do you find features?

POS tag every sentence, keep the nouns, lemmatize them, drop a small list of nouns that are not features, and count. The most frequent nouns are the features. This idea is from Hu and Liu (2004).

Q10. Why is the negative F1 lower than positive?

There are only 872 negative reviews against 5,107 positive ones, so the model has fewer negative examples to learn from. I used class_weight="balanced" to reduce this effect.

Q11. Why is positive_% high for every feature?

Because about 77% of the reviews are 4-5 stars. So "disliked" means "less liked than the other features", not hated. That is why I compare features with each other.

Q12. What is extractive vs abstractive summarization?

Extractive picks real sentences from the reviews (what I did). Abstractive writes new sentences, like a large language model would. Extractive cannot invent anything, so it is safer and easy to check.

Q13. What would you improve?

Link each opinion to its nearest feature instead of the whole sentence, merge synonyms (cord/cable), try a pretrained model like BERT, and build a small web page for live use.

Q14. Where is your data from?

The public Amazon Reviews 2023 dataset (McAuley Lab, UC San Diego), Electronics category. I kept reviews that mention headphones, earbuds or earphones and removed ones about headphone jacks or adapters.
